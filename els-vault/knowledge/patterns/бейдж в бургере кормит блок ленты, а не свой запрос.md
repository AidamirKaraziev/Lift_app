# Бейдж в бургере кормит блок ленты, а не свой запрос

Число непросмотренных у пункта «Работы» — глобальный
`ValueNotifier<int> unreviewedWorksCount`
(`screns/submitted_works/unreviewed_counter.dart`), который читает
`UnreviewedChip` в бургере. Первое значение кладёт оболочка в `initState`
при входе; дальше его обновляет `WorksBloc` тем же тактом, что и ленту:

```dart
final int unreviewed = await _repository.unreviewedCount();
if (serial != _serial) return;      // устаревший ответ бургер не трогает
unreviewedWorksCount.value = unreviewed;
```

`unreviewedCount()` — отдельный лёгкий метод репозитория: считает по всему,
что видно человеку, а не по странице на руках — на ней может не быть ни
одной сданной.

## Почему так

- Механик сдал — число выросло за такт, прораб нажал «проверил» — упало,
  не дожидаясь захода в раздел. Свой таймер у бейджа дал бы второй опрос
  с тем же интервалом.
- Число кладёт блок, а не репозиторий: блок знает, чей ответ настоящий
  (`_serial`), и устаревший ответ не должен менять бургер, как не меняет
  ленту.

## Что важно не забыть

- Не вышло получить число — остаётся прежнее; лента важнее чисел над ней
  ([[живой экран обновляется тихо - своё событие без Loading и без эмита на сбое]]).
- Оболочка обязана положить первое значение сама: до первого захода в
  «Работы» блока ещё нет, и без `initState` бейдж покажет ноль.
- Bloc живёт внутри `WorksScreen` и пересоздаётся при уходе в другой
  раздел; на бейдж это не влияет — notifier глобальный. «Графики» держат
  bloc в оболочке — тот же приём, если ленту захочется не пересоздавать.

Применимо к числам на чипсах отбора и любому счётчику в шапке, который
должен меняться вместе с живым экраном.
