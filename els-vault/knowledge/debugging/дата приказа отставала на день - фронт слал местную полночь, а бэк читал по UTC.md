# Дата приказа отставала на день — фронт слал местную полночь, а бэк читал по UTC

## Симптом

На `make up` в диалоге приказа стояло 15.09, а в PDF печаталось «14» сентября.
На фикстуре и в `flutter test` не ловилось: там дата не проходила через
контейнер.

## Настоящая причина

Контракт отдаёт `date` секундами эпохи. Модель
`appointment_order_draft.dart` собирала их из **местной** полуночи
(`DateTime(y, m, d)`), то есть для Москвы — 21:00 UTC предыдущих суток.
Бэк в контейнере живёт по UTC и читает метку `date_from_timestamp`
(`datetime.utcfromtimestamp(ts).date()`) — получал вчерашнюю дату. Любой
пояс восточнее Гринвича даёт «вчера», западнее — совпадёт случайно.

## Как починили

Коммит `f09266e`. Модель во фронте ходит через `DateTime.utc(...)` в обе
стороны: `toJson` шлёт полночь по UTC, `dateFromTimestamp` читает метку как
UTC и отдаёт календарный день. Сторона бэка не трогалась — `draft` собирает
метку тем же `to_timestamp`, что и раньше.

Хвост: `format_order_date` в `services/appointment_order_pdf.py` печатает
через `datetime.fromtimestamp` — по местному времени процесса, и докстринг
уверяет, что так и надо. Работает, потому что контейнер UTC; запусти бэк
локально в Москве — «вчера» вернётся. Заменить на `utcfromtimestamp` и
поправить докстринг.

## Урок

«Дата» в этом API — **полночь по UTC**, во всех ручках, где ходит
`date_from_timestamp`. Новая модель с датой во фронте собирается через
`DateTime.utc`, а не `DateTime`. Проверять дату только на собранном стеке:
в тестах и превью контейнерного UTC нет, dev-точка `make up` не заменяет.
