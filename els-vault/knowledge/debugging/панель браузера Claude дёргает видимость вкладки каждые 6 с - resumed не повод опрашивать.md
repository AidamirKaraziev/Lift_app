# Панель браузера Claude дёргает видимость вкладки каждые 6 с — resumed не повод опрашивать

Симптом: на `works-live` опрос `updated_since` шёл ровно каждые 6 с вместо
15, хотя `Timer.periodic` стоял на 15.

Причина не в таймере. Панель браузера Claude Code снимает вкладку каждые
6 с и на каждый снимок переключает `document.visibilityState`
(`visibilitychange` парами hidden → visible). Flutter web переводит это в
`AppLifecycleState.paused`/`resumed`, а экран по образцу
`InProgressWorksLive` на каждый `resumed` опрашивал сразу и перезапускал
такт — периодический таймер никогда не доживал до 15 с.

Проверить легко:

```js
window.__ev = []; document.addEventListener('visibilitychange',
  () => window.__ev.push(performance.now()/1000));
```

В обычном браузере таких событий нет, но `resumed` шлётся и на смену
окна, и на возврат с другой вкладки — спамить запросами на каждый нельзя.

## Как починили

`_WorksBodyState` помнит `_lastSync`; на `resumed` опрашивает сразу только
если с прошлого опроса прошло не меньше такта, а живой таймер не
перезапускает (`_startPolling` — no-op, пока `_poller != null`).

## Урок

- Интервал опроса проверять по сети (`read_network_requests` /
  `performance.getEntriesByType('resource')`), а не по коду таймера.
- Попап-меню в панели браузера Claude не кликаются по той же причине —
  визибилити закрывает их до клика. Выпадашки проверять виджет-тестом.
- У других живых экранов (`in_progress_works_live.dart`,
  `work_card_live.dart`) тот же безусловный опрос на `resumed` — при
  случае подтянуть.
