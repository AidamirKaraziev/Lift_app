# Передача: бэк отдаёт PDF приказа, дальше — диалог подключается к API

## Сделано и проверено

- `POST /object/{id}/appointment-order/pdf` (`backend/src/api/api_v1/endpoints/object.py`)
  принимает тело `AppointmentOrderDraft` (тот же формат, что отдаёт `draft`),
  пишет файл в `static/objects/{id}/appointment_order/<uuid>.pdf`, в базу не
  пишет. Ответ `SingleEntityResponse[AppointmentOrderPdfGet]`: `path`, `url`
  (с токеном на минуту, вида `host:port/api/v1/static/<path>?token=…`, без
  схемы — как все ссылки на файлы), `expires_in`.
- Минута прошла → `POST /files/link` с `{"path": <path>}` выдаёт ссылку
  заново; доступ по объекту через `parse_owner`, правил не добавляли.
- Видимость как у `draft` и карточки: чужой объект 403, нет объекта 404.
- Генератор `backend/src/services/appointment_order_pdf.py`: текст дословно
  из образца ПЭЛК №10, два назначения с одним перечнем лифтов, подпись
  «А.С. Фамилия», две строки «ознакомлен» «Фамилия И. О.». Пустые поля —
  прочерк, не ошибка. Портрет A4, шрифт как у дефектной ведомости.
- Должности в черновике теперь в родительном падеже: `FOREMAN_POSITION =
  "прораба сервисного участка"`, `MECHANIC_POSITION = "электромеханика по
  лифтам"` (`backend/src/schemas/appointment_order.py`) — решение
  пользователя, они идут после «Назначить …». ФИО остаётся в именительном.
- Тесты: `tests/test_appointment_order_pdf.py` (7), `tests/test_api_appointment_order.py`
  (+4); `uv run pytest` — 1046 passed; `make lint` чист; снимок OpenAPI +1 путь.
  Коммит `a37ad24`. PDF по фикстуре образца смотрели глазами — принят.
